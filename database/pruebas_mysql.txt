CASO 1: VERIFICAR FUNCIÓN DE CRONOGRAMA DE ACCESO (fn_validar_cronograma)
=================================================================================
Objetivo: Validar si un estudiante puede ingresar al sistema según la fecha/hora actual (NOW()).

-- Prueba 1.1: Validar para un estudiante REGULAR de ESIS (id_escuela = 1, es_ingresante = FALSE)
SELECT fn_validar_cronograma(1, FALSE) AS acceso_permitido;
-- Resultado esperado: 1 (TRUE, dentro del cronograma)

-- Prueba 1.2: Validar para un estudiante INGRESANTE de ESIS (id_escuela = 1, es_ingresante = TRUE)
SELECT fn_validar_cronograma(1, TRUE) AS acceso_permitido;
-- Resultado esperado: 1 (TRUE, dentro del cronograma)

-- Prueba 1.3: Validar para una escuela que no tiene cronograma activo (ej. id_escuela = 99)
SELECT fn_validar_cronograma(99, FALSE) AS acceso_permitido;
-- Resultado esperado: 0 (FALSE, fuera de cronograma o no existe)

CASO 3: DETERMINAR LÍMITE DE CRÉDITOS Y CONDICIÓN (sp_determinar_limite_creditos)
=================================================================================
Objetivo: Clasificar al estudiante según su promedio y determinar su tope de créditos:
- Especial: Menos de 12 créditos (Promedio < 11.0)
- Regular: Entre 12 y 23 créditos (Promedio 11.0 a 13.9)
- Destacado: Hasta 28 créditos y habilita adelanto (Promedio >= 14.0)

-- Prueba 3.1: Estudiante 4 (Promedio 16.80 -> DESTACADO)
CALL sp_determinar_limite_creditos(4, @condicion, @limite_min, @limite_max, @adelanto);
SELECT @condicion AS condicion, @limite_min AS min_cred, @limite_max AS max_cred, @adelanto AS puede_adelantar;
-- Resultado esperado: condicion='DESTACADO', min_cred=12, max_cred=28, puede_adelantar=1

-- Prueba 3.2: Estudiante 3 (Promedio 13.50 -> REGULAR)
CALL sp_determinar_limite_creditos(3, @condicion, @limite_min, @limite_max, @adelanto);
SELECT @condicion AS condicion, @limite_min AS min_cred, @limite_max AS max_cred, @adelanto AS puede_adelantar;
-- Resultado esperado: condicion='REGULAR', min_cred=12, max_cred=23, puede_adelantar=0

-- Prueba 3.3: Estudiante 5 (Promedio 10.20 -> ESPECIAL)
CALL sp_determinar_limite_creditos(5, @condicion, @limite_min, @limite_max, @adelanto);
SELECT @condicion AS condicion, @limite_min AS min_cred, @limite_max AS max_cred, @adelanto AS puede_adelantar;
-- Resultado esperado: condicion='ESPECIAL', min_cred=1, max_cred=11, puede_adelantar=0

CASO 4: AGREGAR CURSO A PROFORMA CON BLOQUEO PESIMISTA (sp_matricular_curso)
=================================================================================
Objetivo: Reservar cupo aplicando 'SELECT ... FOR UPDATE' sobre la sección,
descontando la vacante en tiempo real y sumando los créditos a la proforma.

-- Estado inicial: Verificar vacantes de la sección 1 (Base de Datos II - Grupo A)
SELECT id_seccion, id_curso, grupo, vacantes_totales, vacantes_disponibles, estado 
FROM seccion WHERE id_seccion = 1;
-- Inicialmente: vacantes_disponibles = 35

-- Prueba 4.1: Agregar Sección 1 (4 créditos) a la proforma 1 (Estudiante 3)
CALL sp_matricular_curso(1, 1, @codigo, @mensaje);
SELECT @codigo AS codigo_respuesta, @mensaje AS mensaje_respuesta;
-- Resultado esperado: codigo_respuesta = 200, mensaje_respuesta = 'Asignatura y sección agregadas exitosamente...'

-- Verificar que se descontó la vacante en la sección 1:
SELECT id_seccion, vacantes_disponibles FROM seccion WHERE id_seccion = 1;
-- Resultado esperado: vacantes_disponibles = 34

-- Verificar que se sumaron 4 créditos a la proforma:
SELECT id_matricula, total_creditos, estado FROM matricula WHERE id_matricula = 1;
-- Resultado esperado: total_creditos = 4

-- Prueba 4.2: Intentar agregar otra sección del MISMO curso (ej. Sección 2 de BD II)
CALL sp_matricular_curso(1, 2, @codigo, @mensaje);
SELECT @codigo AS codigo, @mensaje AS mensaje;
-- Resultado esperado: codigo = 400 ('Ya tiene una sección seleccionada para esta asignatura en su proforma.')

-- Prueba 4.3: Agregar más cursos (Sección 3: Ing. Software I - 4 cred, Sección 5: Redes - 4 cred)
CALL sp_matricular_curso(1, 3, @codigo, @mensaje);
CALL sp_matricular_curso(1, 5, @codigo, @mensaje);
SELECT id_matricula, total_creditos FROM matricula WHERE id_matricula = 1;
-- Resultado esperado: total_creditos = 12

CASO 9: CANCELACIÓN AUTOMÁTICA POR TIMEOUT DE 5 MINUTOS (sp_cancelar_reserva_timeout)
=================================================================================
Objetivo: Demostrar que si un alumno deja abierta la sesión sin confirmar durante
5 minutos, el sistema libera los cupos automáticamente para otros estudiantes.

-- Crear proforma de prueba para estudiante 5 (Especial)
INSERT INTO matricula (id_matricula, id_estudiante, id_periodo, total_creditos, estado, es_editable) 
VALUES (2, 5, 1, 0, 'PROFORMA', TRUE);

-- Estudiante 5 reserva Sección 7 (Sistemas Operativos Grupo A, vacantes = 35)
CALL sp_matricular_curso(2, 7, @c, @m);
SELECT vacantes_disponibles FROM seccion WHERE id_seccion = 7; -- vacantes = 34

-- Simular expiración de 5 minutos por inactividad:
CALL sp_cancelar_reserva_timeout(5, @codigo, @mensaje);
SELECT @codigo AS codigo, @mensaje AS mensaje;
-- Resultado esperado: codigo = 200 ('Tiempo de 5 minutos expirado. Reservas temporales liberadas.')

-- Verificar que la vacante de la sección 7 volvió a subir a 35:
SELECT id_seccion, vacantes_disponibles FROM seccion WHERE id_seccion = 7;
-- vacantes_disponibles = 35 (liberada)

-- Verificar que la matrícula pasó a estado 'CANCELADA':
SELECT id_matricula, estado, es_editable FROM matricula WHERE id_matricula = 2;
-- estado = 'CANCELADA'
